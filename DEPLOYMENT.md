# Deploying Youth Labour Explorer

## What changed

The running app reads only `artifacts/`: the saved trained model, metadata,
evaluation tables, and precomputed group statistics. It never reads `outputs/`
or `NLFS Dataset/` at runtime. The trained model and original notebooks remain
unchanged. The deployment files have been pushed to the public
[GitHub repository](https://github.com/Melchizedek-Madaki/Nigeria-Youth-Labor-Underutilization)
on branch `main`. The app is deployed on Streamlit Community Cloud:
[open the live app](https://nigeria-youth-labor-underutilization-zrpvsbfkpsrqf8h2uefjqr.streamlit.app/).

## Build locally

With the existing local model and descriptive preparation outputs:

```powershell
.venv\Scripts\python.exe prepare_public_artifacts.py
.venv\Scripts\python.exe check_public_artifacts.py
```

This produces `artifacts/` and a standalone **`deployment_bundle/`**. It copies
only explicit runtime files; raw survey records, original and executed
notebooks, images of survey cells, logs, secrets, backups, and virtual
environments are omitted. The source file list and SHA-256 hashes are recorded
locally in `public_artifacts_manifest.json`.

The builder rejects unexpected files in an existing bundle. Do not use that
folder for unrelated work. Python bytecode caches generated by running the
bundle are excluded from the file audit and do not need uploading.

## How the aggregate explorers work

The exporter computes statistics locally from the aligned cleaned model
sample. Class charts retain quarterly weighted/unweighted demographic
comparisons. The pay explorer offers a quarter and one focus dimension:
all employed youth, state of residence, urban/rural residence, occupation, or
sex. Within that group, published work breakdowns are available. Arbitrary
combinations of multiple focus filters are not exported.

Group medians are precomputed directly, so the app never tries to average
medians. Counts are rounded to five, pay medians to ₦500, percentages to one
decimal, and median hours to one decimal. The original quarterly pay threshold
is preserved without re-estimation when selecting a group.

Minimum group size is 30. Small work groups are withheld; a companion group is
also withheld when needed to avoid recovering a lone small group by subtraction.
Indicator rates with a positive numerator or complement below 10 are withheld.
Pay bands use companion suppression. Class breakdowns with positive class
cells below 10 are withheld as a whole. Medians require at least 30 usable
observations. Downloads contain only the published group summaries.

These measures reduce disclosure risk but are not formal differential privacy,
an anonymisation certification, or a guarantee against every possible inference.
[NBS terms](https://nigerianstat.gov.ng/page/terms) and dataset-specific publication
terms still apply to derived outputs. The app's scientific limitations remain
described in the main README.

## Verify the isolated runtime

The bundle has no raw survey folder or respondent exports. Test all app pages
against that directory using the local environment:

```powershell
$env:YOUTH_APP_ROOT = (Resolve-Path deployment_bundle).Path
.venv\Scripts\python.exe check_app.py
Remove-Item Env:YOUTH_APP_ROOT
```

Start the bundle manually if desired:

```powershell
.venv\Scripts\python.exe -m streamlit run deployment_bundle\streamlit_app.py
```

The dependency pins match the completed Python 3.13 training environment.
Local checks do not replace a fresh Linux/cloud installation test.

## GitHub and Streamlit Community Cloud

1. Choose the repository owner, name, visibility, and software licence.
2. Git is already initialised **inside the deployment bundle**, with `main` tracking `origin/main`. The original research workspace remains separate.
3. Inspect the exact staged-file list against the list above. The included `.gitignore` excludes bytecode, local environments, and secrets. Commit and push that reviewed set.
4. Connect the intended GitHub account to Streamlit Community Cloud.
5. Create an app, choose the actual repository and branch, and set the entry point to **`streamlit_app.py`**.
6. Choose **Python 3.13**, if supported by the host, to match the saved pipeline's environment. If changing versions, verify model compatibility and rebuild where needed.
7. Deploy using the root `requirements.txt`. No notebook execution or NBS data download is needed on the host.
8. Check every page, predictions, withheld-group behaviour, filters, downloads, model loading, and memory on the hosted environment. Then record and share its public URL.

No current runtime secrets are required. Put future secrets in the hosting
service's secret settings, never in source control.

Official instructions: [deployment](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app)
and [dependencies](https://docs.streamlit.io/deploy/concepts/dependencies).
